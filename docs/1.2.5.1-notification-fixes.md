# 1.2.5.1 通知渠道修复与界面性能优化

日志更新日期：2026-11-14。发布基准为正式标签 `10-1.2.5`，本次提交版本为 `1.2.5.1`，内部构建号为 `11`；提交和推送本身不代表已发布正式版。

升级后，旧版单渠道手动开关需要重新选择：旧数据缺少用户身份，不能可靠判断属于主应用还是双开应用。正则规则及整应用白名单保持有效。

## 修改

- 查询渠道只记录快照，不修改返回的渠道对象，也不在查询回调中持久化系统通知设置。配置变化由独立任务复制渠道后，通过系统更新接口生效。
- 渠道记录、原始状态和手动开关使用 `user:N|包名|渠道ID`，隔离主用户与双开用户。界面显示所属用户，通知菜单跳转携带用户身份。
- 渠道 Hook 只接受已知的系统 helper 签名，根据目标包名及 UID 确定归属。通知入队区分目标包和代理发送包；无法识别的方法签名直接放行。
- 原始状态原子保存成功后才允许关闭渠道；系统恢复成功后才删除对应的保存状态。
- 检测到的渠道内容没有变化时跳过重复记录；读取 Hook 侧快照时先加载既有记录，供配置同步使用。
- 无 Root 模式同样按通知所属用户记录渠道和读取手动开关，保持两种模式的渠道标识一致。

## 界面与动效

- 首帧之后预建统计页和渠道页，并在统计页创建后加载数据，减少首次进入时的等待和内容替换。
- 非当前页面保留布局并移至屏幕外，关闭其焦点和无障碍访问；切换页面时恢复，避免反复使用 `GONE` 引起整页重新布局。
- 渠道长列表仅绘制视口及附近的行，远处行保持尺寸但暂停绘制，保留滚动范围及渠道跳转位置。
- 弹簧动画沿用最近测得的帧间隔作为首帧步长，减少高刷新率屏幕上按固定 60 Hz 步长启动时的跳动。

## 构建与产物记录

- `app/build.gradle` 使用版本名 `1.2.5.1`、构建号 `11`，新增仅用于单元测试的 Mockito 依赖。
- `app/release/output-metadata.json` 的既有改动记录了此前 `1.2.5`、构建号 `10` 的 APK；它是旧产物元数据，新构建的版本以 `app/build.gradle` 为准。

## 升级行为

旧版 `包名|渠道ID` 记录缺少用户身份，保留但不自动分配给主用户或双开用户。旧渠道列表会在重新观察到渠道后补充；旧的单渠道手动开关需要重新选择。正则规则及整应用白名单保持有效。旧版已经写入系统的关闭状态不会被猜测性恢复，可对明确归属的渠道手动选择允许。

## 验证范围

新增 15 项 JVM 回归测试，覆盖查询不修改渠道、主用户与双开状态独立保存和恢复、旧数据隔离、保存失败不允许拦截、代理包与目标包区分及未知签名放行。全部 85 项单元测试通过，失败和错误均为 0；Debug APK 构建检查通过。复核命令（Windows PowerShell）：
